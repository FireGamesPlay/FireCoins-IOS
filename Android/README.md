# Fire Coins для Android

Нативное приложение Fire Coins для Android. Интерфейс реализован на Kotlin, Jetpack Compose и Material 3.

## Открытие и сборка

1. Откройте каталог `Android/` в Android Studio.
2. Используйте JDK 17 для Gradle.
3. Установите Android SDK и Build Tools, указанные в настройках проекта.
4. Запустите приложение на устройстве с Android 8.0 или новее либо на эмуляторе.

Workflow `.github/workflows/android-build.yml` собирает отладочный APK. Подписанный релизный APK создаёт отдельный workflow `.github/workflows/android-release.yml`.

## Вход и сессия

Вход выполняется по одноразовому коду-приглашению. Сервер выдаёт короткоживущий токен доступа и токен обновления. Секреты сессии сохраняются в защищённом хранилище Android Keystore. Коды приглашений не встраиваются в APK.

## Данные и API

Базовый HTTPS-адрес API задан в `data/ApiClient.kt`. Приложение не подключается к SQLite напрямую: баланс, история, заявки, заметки и права доступа определяются сервером.

В профиле доступны настройки аккаунта, перевыпуск собственного кода, аватар и переключатель тестовой среды. Тестовая среда использует отдельную пустую БД и не должна изменять рабочую базу. В разделе Danger Zone администратор может запросить сброс текущей среды после ввода точной фразы подтверждения или запланировать перезапуск API.

## Фотографии-доказательства и аватары

Фотографии-доказательства и аватары загружаются на VPS по авторизованному HTTPS API и хранятся отдельно от Telegram. Сервер проверяет тип и размер изображения. Доступ к аватарам привязан к активной сессии и роли аккаунта.

## Системные уведомления

Android получает push-уведомления через Firebase Cloud Messaging (FCM). Для включения доставки нужен Firebase-проект и файл `google-services.json`, соответствующий приложению `ru.firedev.firecoins`. Токен устройства регистрируется на сервере под вошедшим аккаунтом; после выхода токен отзывается. Для CI можно сохранить Base64 содержимое соответствующего `google-services.json` в секрете `ANDROID_GOOGLE_SERVICES_JSON_BASE64`.

На Android 13 и новее приложение запрашивает разрешение `POST_NOTIFICATIONS`. Пока Firebase-конфигурация не добавлена, приложение продолжает работать без системных push-уведомлений.

## Подписанный APK

Workflow `.github/workflows/android-release.yml` использует секреты GitHub Actions:

- `ANDROID_KEYSTORE_BASE64` — Base64 содержимое приватного JKS/PKCS12 keystore;
- `ANDROID_KEYSTORE_PASSWORD` — пароль хранилища ключей;
- `ANDROID_KEY_ALIAS` — псевдоним ключа;
- `ANDROID_KEY_PASSWORD` — пароль ключа.

Keystore следует создать один раз на доверенном локальном компьютере и хранить в приватной резервной копии. Не добавляйте файл, Base64-содержимое или пароли в репозиторий и переписку. Все обновления должны подписываться тем же ключом, иначе Android не установит их поверх текущей версии.

## Проверка сборки

- Отладочный APK: `gradle --no-daemon :app:assembleDebug`.
- Релизный APK: `gradle --no-daemon :app:assembleRelease`.
- Проверка подписи: `apksigner verify --verbose <путь-к-apk>`.

Перед выпуском проверьте на реальном устройстве вход по приглашению, восстановление сессии, историю, заметки, заявки, загрузку фотографий, аватар, переключение тестовой среды и получение push-уведомлений.

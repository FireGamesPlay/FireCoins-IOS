# Архитектура Fire Coins

## Принципы

1. SwiftUI отвечает за отображение и пользовательский ввод.
2. `AppStore` предоставляет экранам наблюдаемое состояние и вызывает команды доменного слоя.
3. `FireCoinsRepository` задаёт асинхронный контракт хранения и операций — он подходит и для будущего сетевого API.
4. `InMemoryFireCoinsRepository` — временный адаптер без БД и сети.
5. UI не меняет баланс напрямую: все изменения проходят через методы репозитория.

## Роли

- `artemiy`: просмотр баланса и истории, спор по недавней операции, запрос вывода, рулетка, заметки.
- `father`: всё перечисленное для просмотра, плюс панель управления — начисления/списания, решения по спорам и заявкам.

## Доменные правила

- Доступны только два заранее заданных кода приглашения.
- Максимум два раунда рулетки за скользящие семь дней.
- Ставка должна быть положительной и не превышать доступный баланс.
- Запрос на вывод создаётся без немедленного списания; списание происходит при одобрении.
- Причины штрафа «Неубранные трусы» и «Оставленные тапки» требуют фото.
- Администраторские списания могут увести баланс в минус, как в исходной логике бота; рулетка и одобрение вывода требуют достаточного баланса.
- Спорить можно только с одной из десяти последних операций, у которой ещё нет результата спора.
- Одобренный спор создаёт компенсирующую операцию; исходная запись не удаляется.

## Что заменить при подключении сервера

- Реализовать `FireCoinsRepository` поверх API.
- Перенести приглашения, назначение ролей и сессии на сервер.
- Выполнять начисления, списания, ставки, выплаты и одобрения в транзакциях БД на сервере.
- Хранить фото в объектном хранилище, а в БД — безопасную ссылку и метаданные.
- Добавить аудит администратора, защиту повторных запросов (idempotency keys), авторизацию и уведомления.
- Не доверять локальным значениям баланса, роли и результату рулетки.
